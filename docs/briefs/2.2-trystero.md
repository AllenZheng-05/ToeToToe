# Brief 2.2: the WebRTC link (Trystero)

**Goal.** The real peer-to-peer connection: a `RawLink` (see `src/core/types.ts`) backed by Trystero, so two browsers anywhere can join the same room with no server of ours. Another task builds the two-player `Transport` on top of any `RawLink`; you only supply the link.

**Read first:** `CLAUDE.md`, `docs/NETWORKING.md`, `src/core/types.ts` (`RawLink`). Then read Trystero's own README and type definitions in `node_modules/trystero` after installing it: its API has changed between versions, so follow the installed version, not memory.

**Files you own:** `src/net/trysteroLink.ts`, `src/net/netConfig.ts`, `tests/unit/netConfig.test.ts`, and the `trystero` entry in `package.json` / `pnpm-lock.yaml`. Touch nothing else. Other agents are editing `src/net/pairing.ts`, `room.ts`, `codes.ts`, `memoryHub.ts`, `broadcastLink.ts` and the app shell at the same time.

## Work

1. `pnpm add -E trystero@0.27.0` (exact pin, no `^`). If that version does not install, use the newest that does and report it.
2. `src/net/netConfig.ts`:
   ```ts
   export type LinkStrategy = 'nostr' | 'torrent' | 'mqtt' | 'supabase'; // whichever of these the installed Trystero actually ships; drop the ones it does not
   export interface NetConfig {
     /** Namespaces our rooms on the public handshake networks. */
     appId: string;                 // 'toetotoe.allenzheng.com'
     strategy: LinkStrategy;        // Trystero's default strategy for the installed version
     /** Optional relay/tracker URL overrides passed through to Trystero. */
     relayUrls?: string[];
     /** Optional extra ICE servers (a TURN relay can be added here later). */
     iceServers?: RTCIceServer[];
   }
   export const DEFAULT_NET_CONFIG: NetConfig;
   /** Reads optional overrides from Vite env (VITE_NET_STRATEGY, VITE_NET_RELAYS comma-separated, VITE_TURN_URL / VITE_TURN_USERNAME / VITE_TURN_CREDENTIAL); pure function of an env-like object so it can be unit tested. */
   export function netConfigFromEnv(env: Record<string, string | undefined>): NetConfig;
   ```
3. `src/net/trysteroLink.ts`:
   ```ts
   /** Joins the Trystero room for this code. The strategy module is loaded with a dynamic import so only the chosen one is bundled into a chunk. */
   export function createTrysteroLink(roomCode: string, config?: NetConfig): Promise<RawLink>;
   ```
   Map `RawLink` onto Trystero: one action for JSON data (`send` / `onData`), one action for binary with metadata and progress (`sendBinary` / `onBinary` / `onBinaryProgress`; use Trystero's own chunking and progress callbacks), `onPeerJoin`, `onPeerLeave`, `leave`. Peers already present when a listener is attached must be reported to it (replay known peers), because the pairing layer attaches its listeners right after the link is created. `send(null, …)` broadcasts. Never throw from `send` when a peer has just gone; swallow and ignore. `selfId` is Trystero's own id.
   Note Trystero action names have a short byte-length limit; keep them short (`d`, `b`).
4. `tests/unit/netConfig.test.ts`: defaults; each env override; bad strategy falls back to the default; TURN server only added when a URL is present.

The link itself cannot be tested without two browsers and the public handshake network; do not try to reach the network from tests. Make sure `pnpm build` succeeds with the dynamic import and report the size of the Trystero chunk(s) from the build output.

## Out of scope

Pairing, rooms, UI, TURN provisioning. Do not wire the link into the app; a later task does that.
