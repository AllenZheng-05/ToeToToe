# Brief 6.1: accounts and saving puppets across devices (Supabase)

**Goal.** Optional saving across devices: guest-first sign-in, a profile with a display name, and two-way sync of saved puppets, all of which quietly do nothing when Supabase is not configured or not reachable. The game must run fully with no environment variables, and nothing in a match may depend on any of this. There is no Supabase project to test against, so the remote side sits behind a small interface with a fake for tests.

**Read first:** `CLAUDE.md` (rule 5), `docs/DATA.md`, `docs/SUPABASE.md`, `supabase/migrations/20261116000000_init.sql` (table, column, bucket and object-path names you must match), `.env.example`, `src/data/store.ts`, the UI kit (`src/ui/kit/kit.ts`, `dev/uikit.ts`), and the installed `@supabase/supabase-js` 2.119.0 typings (follow the installed API, not memory).

## Interfaces

```ts
// src/data/remote.ts — everything the app needs from a backend; no Supabase types leak out of supabaseRemote.ts
export interface RemoteUser { id: string; email: string | null; isGuest: boolean }
export interface RemotePuppetRow { id: string; name: string; updatedAt: number /* epoch ms */ }
export interface Remote {
  currentUser(): Promise<RemoteUser | null>;                 // restores a persisted session if there is one
  signInGuest(): Promise<RemoteUser>;
  attachEmail(email: string): Promise<void>;                 // links an email to the current (guest) account
  signOut(): Promise<void>;
  getProfileName(): Promise<string | null>;
  setProfileName(name: string): Promise<void>;
  listPuppets(): Promise<RemotePuppetRow[]>;
  uploadPuppet(p: { id?: string; name: string; head: Blob; sock: Blob; sword: Blob; updatedAt: number }): Promise<RemotePuppetRow>;
  downloadPuppet(id: string): Promise<{ row: RemotePuppetRow; head: Blob; sock: Blob; sword: Blob }>;
  deletePuppet(id: string): Promise<void>;
}
/** Null when VITE_SUPABASE_URL or VITE_SUPABASE_ANON_KEY is missing or malformed. Pure. */
export function supabaseConfigFromEnv(env: Record<string, string | undefined>): { url: string; anonKey: string } | null;

// src/data/supabaseRemote.ts
/** Loads @supabase/supabase-js with a dynamic import (so it is a separate chunk that unconfigured sites never download) and implements Remote against the schema in the migration: tables `profiles`, `puppets`; private bucket `puppets` with objects `<user id>/<puppet id>/head.png|sock.png|sword.png`. */
export function createSupabaseRemote(config: { url: string; anonKey: string }): Promise<Remote>;

// src/data/account.ts
export type AccountStatus = 'off' | 'signedOut' | 'guest' | 'member' | 'unreachable';
// off: not configured. unreachable: configured but the last call failed or timed out (the database may be asleep).
export interface Account {
  readonly status: AccountStatus;
  readonly user: RemoteUser | null;
  /** Restores a session if there is one. Never rejects; sets 'unreachable' on failure. */
  init(): Promise<void>;
  /** Guest sign-in, then push the display name. Resolves false (status 'unreachable') on failure. */
  saveAcrossDevices(displayName: string): Promise<boolean>;
  attachEmail(email: string): Promise<{ ok: true } | { ok: false; message: string }>; // plain messages; validates the address shape first
  signOut(): Promise<void>;
  /** Runs syncPuppets when signed in. Resolves a summary; never rejects. */
  sync(): Promise<SyncSummary | null>;
  onChange(cb: () => void): Unsubscribe;
}
/** `remote` is null when not configured (status stays 'off' and every method is a harmless no-op). Every remote call is raced against `timeoutMs` (default 6000) using the injected `defer`. */
export function createAccount(deps: { remote: Remote | null; store: Store; timeoutMs?: number; defer?: (fn: () => void, ms: number) => void }): Account;

// src/data/puppetSync.ts
export interface SyncSummary { uploaded: number; downloaded: number; deletedRemote: number; failed: number }
/**
 * Two-way sync between the local Store and the Remote:
 * - local puppets with no `remoteId` are uploaded and get their `remoteId` saved;
 * - local puppets with a `remoteId` whose `updatedAt` is newer than the remote row are re-uploaded; older ones are replaced by the remote copy (last write wins);
 * - remote puppets unknown locally are downloaded (validated with `checkDrawingBytes` from src/puppet/validate.ts before storing; invalid ones are skipped and counted as failed);
 * - remote ids listed in the `deletedRemoteIds` setting (puppets the player deleted locally) are deleted remotely and removed from the list;
 * - a local puppet whose `remoteId` no longer exists remotely is kept and re-uploaded.
 * One failing puppet does not stop the rest. Never rejects.
 */
export function syncPuppets(store: Store, remote: Remote): Promise<SyncSummary>;
/** Call when the player deletes a saved puppet locally, so the next sync removes the remote copy. */
export function recordLocalDelete(store: Store, puppet: { remoteId?: string }): Promise<void>;
```

## Panel

`src/account/panel.ts`: `createAccountPanel({ account, store, getDisplayName }): { root: HTMLElement; destroy(): void }`, built from the UI kit, small enough to sit in a corner of the title or workshop screen. States:

- `off`: nothing but a typed note "Drawings are saved in this browser." (no button).
- `signedOut`: that note plus a button "Save across devices". Pressing it signs in as a guest and syncs; no sign-up form.
- `guest`: "Saving across devices as a guest." plus "Add an email" (a field and a button; on success: "Check your inbox to confirm."), "Sync now", and the last sync summary in words ("2 sent, 1 fetched").
- `member`: the email, "Sync now", "Sign out".
- `unreachable`: "Can't reach the saving service right now. Your drawings are still saved in this browser." plus "Try again". Never an error screen, never a blocking dialog.
- Collect nothing but a display name and, optionally, the email the player types. Say so in one line under the email field: "Only your display name and drawings are stored."

`dev/account.html` + `dev/account.ts` (served at `/dev/account.html`): mounts the panel with a fake in-memory `Remote` (a `?state=` switch for each status, including a remote that always times out) so the states can be looked at. Screenshot each state with a throwaway Playwright script against `pnpm exec vite --port 4178 --strictPort` (Chromium is in the project, `PLAYWRIGHT_BROWSERS_PATH=0`; do not commit the script), check them by eye, stop the server.
