# Brief 1.4: app shell, plain-shapes stage, HUD, debug overlay, bot match

**Goal.** Make the game playable in one browser against the bot: a title screen, a duel scene drawn with plain shapes, bars and banners, a victory screen with a rematch, and the debug overlay. No final art yet (milestone 3 restyles everything), so keep visuals simple but structure the code so the art can be swapped in: rules live in `DuelSession`, the renderer only draws a `DuelView`.

**Read first:** `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/GAME.md`, `docs/DESIGN.md` (colours and vocabulary only), `src/core/types.ts`, and the public APIs of `src/core/session.ts`, `src/core/beat.ts`, `src/core/tunables.ts`, `src/net/bot.ts`, `src/audio/engine.ts`, `src/audio/click.ts`, `src/audio/sfx.ts`, `src/input/pointer.ts`. Do not edit those files; if one has a bug or a missing capability, work around it minimally and report it.

**Files you own:** `index.html`, `src/main.ts`, `src/style.css`, everything under `src/app/`, `src/scenes/`, `src/stage/`, `src/ui/`, `src/debug/`, and `tests/unit/layout.test.ts`, `tests/unit/params.test.ts`. Touch nothing else. Add no dependencies (pixi.js 8.23.0 is installed; check its v8 API in `node_modules/pixi.js` typings rather than relying on memory of older versions: `new Application()` then `await app.init({...})`, `Graphics` uses `.circle().fill().stroke()`).

```ts
// src/scenes/types.ts
export interface MatchSetup {
  localPlayer: PlayerId;
  names: [string, string];            // display names, index = PlayerId
  transport: Transport;
  grid: BeatGrid;
  firstAttacker: PlayerId;
  firstPhrase: number;
  /** Called every frame before the local session's update (the bot opponent hooks in here). */
  tick?: () => void;
  /** Called once when the duel scene is left. Stop music, dispose the opponent. */
  dispose?: () => void;
  /** Called when the player asks for a rematch on the victory screen; resolves to the next setup. */
  rematch?: () => Promise<MatchSetup>;
}
export interface Scene { enter(): void | Promise<void>; exit(): void; }
```

- `src/app/app.ts`: the `App` object that owns the `AudioEngine`, the live `Tunables` (from `createTunables(params.tunables)`), the Pixi stage, the DOM overlay root, the scene manager (`go(scene)` exits the current scene and enters the next), `params`, and one frame loop. The frame loop uses `requestAnimationFrame`, **plus a `setInterval` of 100 ms that calls the same update when the page is hidden** so a background tab still commits and resolves its phrases. (This polls the clock; it does not time anything. Say so in a comment.)
- `src/stage/stage.ts`: creates the Pixi `Application`, a root container scaled by `fitStage` on resize, and a sibling DOM overlay `div` that is transformed with the same scale and offset so DOM elements can be positioned in 1280x720 design pixels. Page background is the cutting-mat green `#2F6B52`.
- `src/stage/duelRenderer.ts`: draws a `DuelView` every frame with Pixi `Graphics` and `Text`, plain shapes only: a pale backdrop for the stage and a slightly darker play rect; planted strikes as red numbered discs joined by a red line with the newest yellow; targets as yellow discs with an ink ring and number, a ring that shrinks to the disc edge at `timeToHit = 0` (start shrinking one beat before), green with a tick when parried, greyed and crossed when missed; each puppet as a thick line from its base on the ledge (player 0 at design x 310, player 1 at x 970, y 640) to its sword tip. The local tip follows the pointer; the opponent's tip eases toward its most recent strike or parried target. No per-frame filters.
- `src/ui/hud.ts` (+ CSS in `src/style.css`): per player the display name, a red **Health** bar and a blue **Stamina** bar with those exact labels, on the left and right of the ledge area; eight phrase dots in the middle with the current half-beat lit; an act counter ("Act 2 of 3") and act wins; a big banner: "ATTACK!" when the local player attacks, "PARRY!" when defending, the count-in number during a count-in, "WATCH" when it is the opponent's phase to act; short grade pop-ups "Bravo!", "Good", "Miss" at the target position; a "Winded" tag on a winded player; a brief "Not enough stamina" note on a `rejected: stamina` event. Give elements stable class names and `data-testid`s (`health-0`, `health-1`, `stamina-0`, `stamina-1`, `banner`, `act-counter`); expose the numeric values as `data-value` attributes for tests.
- `src/scenes/title.ts`: the title "Toe to Toe", a display-name field (saved to `localStorage`, default "Player"), and three buttons: "Create a room" and "Join a room" (present but disabled with the note "coming in the next milestone"), and "Practise against the bot" (`data-testid="play-bot"`). Clicking the bot button calls `engine.resume()` (it is the user gesture), builds a bot `MatchSetup`, and goes to the duel scene.
- `src/scenes/botMatch.ts`: `createBotMatch(app): MatchSetup`. BPM is `foldBpm(params.bpm ?? 120)`; `grid.startTime = clock.now() + 0.6`; `firstPhrase = tunables.countInPhrases`; first attacker is player 0; starts the click loop with `engine.playLoop(createClickBuffer(ctx, bpm, 16), { startTime: grid.startTime, loopEnd: clickLoopSeconds(...) })`; opponent from `createBotOpponent` named "Bot"; `tick` calls the opponent's `update()`; `dispose` stops the music and disposes the opponent; `rematch` builds a fresh one. When `params.autoplay` is set, also create a `BotDriver` on the local session (the duel scene should allow this through an optional `MatchSetup` extension or a hook; keep it tidy).
- `src/scenes/duel.ts`: creates the local `DuelSession` from a `MatchSetup` (using `app.engine.clock`, `app.tunables`, and the stored input offset, 0 for now), attaches pointer input with `getPlayRect` from the current fit, forwards `onDown` clicks that are `inside` to `session.pointerDown`, calls `setup.tick`, `session.update()`, then renders `session.view()` and updates the HUD each frame. Plays sound effects on session events (`plant`, `bravo`, `good`, `miss`, `actOver`). On `matchOver` goes to the victory scene. If the transport state becomes `closed` mid-match, shows "Your friend left" and returns to the title.
- `src/scenes/victory.ts`: "NAME WINS!" with the winner's display name, the act score, and buttons "Rematch" (`data-testid="rematch"`) and "Back to title".
- `src/debug/overlay.ts`, shown only with `?debug=1`: a corner panel listing, updated every frame: beat and phrase counter (clock phrase, slot position), audio clock time, frame rate, the last judged input offset in ms and the running mean of the last 20, connection state and round-trip time from the transport, the bot's accuracy (editable), and the current phrase as data (JSON of `state.phase`, `phrase`, `attacker`, `strikes`, `results`). Below it, a number input for **every** key of `Tunables`, editing the live object in place. Also, in debug mode only, set `window.__ttt = { app, session }` (the current session or null) so browser tests can read state.

## Rules

- All beat timing comes from `app.engine.clock`. No `setTimeout`/`Date.now`/`performance.now` for anything on the beat. (CSS transitions for pop-ups fading are fine.)
- Inputs in a match are the pointer and a click or tap only. No keyboard handlers in the duel.
- The renderer and HUD contain no rules: they only read `DuelView`, `DuelState` and session events.
- No per-frame allocation storms: reuse Graphics objects where reasonable.
- No console errors or warnings in normal play.
