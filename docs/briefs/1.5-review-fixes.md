## Fixes

1. **Late-handled clicks are lost** (`session.ts`, the auto-miss in `update()` and the `update()` call at the top of `pointerDown`). Add tunable `inputGraceMs` (default 60). A strike is auto-missed only when `now > slotTime + (goodWindowMs + inputGraceMs)/1000`. Judging still uses the click's stamped time, so a click stamped at +90 ms and handled at +130 ms is a Good. The resolve at the end of a defend phrase must still wait for nothing extra: at the phrase end any strike still unjudged is resolved as a miss by the reducer as now (so a slot-7 strike at very high tempo keeps the shorter of the two limits). Test: click stamped +90 ms, `pointerDown` called when the clock reads +130 ms, expect `good`; a click stamped +130 ms is still a miss or ignored per the windows; with the bot, restore the full window use if that is now safe, or leave its 80% margin and say which.
2. **An attacker's early click on slot 0 is swallowed** (`session.ts`, `pointerDown`). When the local player is the defender of phrase `D`, the reducer is still in `defend`, and a click's `nearestSlot(adjusted)` is `(D + 1, slot 0)`: first see whether the click parries an unjudged target with grade `bravo` or `good`; if so it is a parry as today. Otherwise hold it (at most one held click; a second replaces nothing, it is ignored). Immediately after this session applies its own `resolve` for `D`, if the state is now `attack`, the local player is the attacker and `state.phrase === D + 1`, plant the held click through the normal plant path (events and messages as usual); otherwise drop it (for example the act just ended). Tests: a click stamped 40 ms before the attack phrase and handled before the boundary ends up planted in slot 0 and is seen by the other side; the same click when the act ends at that resolve is dropped without error; a click that is a Good parry of a slot-7 target stays a parry.
3. **Latency is re-read on every `resume()`** (`engine.ts`). Set `clock.latencySec` only the first time the context actually reaches `running`; later `resume()` calls leave it alone.
4. **A loop started late, or with a start time only just ahead, is misaligned** (`engine.ts`, `playLoop`). If the context start time is less than 50 ms ahead of `context.currentTime`, start at `currentTime + 0.05` and advance the buffer position by the same amount (wrapped into the loop region) so the beat grid stays exact. Factor the arithmetic into a small pure exported helper, `planLoopStart(args): { when: number; position: number }`, and unit test it (future start, late start, late by several loops, with a first-beat offset and a loop region).
5. **`timeOfEvent` and the interpolation cap** (`engine.ts`, `AudioClock`). `timeOfEvent` must never return more than `now()`. The interpolation cap should be the larger of the configured quantum and the largest step in context time observed so far (capped at 50 ms), so the clock does not stair-step on systems where `currentTime` moves in 10 ms jumps. Keep it monotonic. Tests for both, plus: changing `latencySec` upward after `now()` has been read never makes `now()` go backwards.
6. **Untrusted input in the session** (`session.ts`). An incoming `parry` or `resolve` whose grade is not exactly `bravo`, `good` or `miss` is ignored (for `resolve`, bad entries are treated as absent). An incoming `commit` whose strikes fail validation must not leave the match stuck: apply `commit` with the strikes this session already knows from `plant` messages and emit `desync`. Tests for each.

Do not change behaviour beyond these six items. Update `DEFAULT_TUNABLES` and its test for `inputGraceMs: 60`.
