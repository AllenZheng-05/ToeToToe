Pairing rules (control messages are wrapped, e.g. `{ c: 'offer' | 'accept' | 'full' | 'bye', ... }`, game messages as `{ m: Message }`; ignore anything malformed):

- State starts `waiting` for the host and `connecting` for the guest.
- A guest, on seeing any peer (join event or already present), sends that peer `offer`. The host answers the first offer with `accept`, records that peer as its partner and becomes `open`; it answers every later offer from another peer with `full`. A guest that receives `accept` records the sender as its partner and becomes `open`; a guest that receives `full` becomes `full` and leaves the link. Hosts ignore offers' absence: two hosts in one room never pair (each ignores the other).
- A guest that is `connecting` and has had no `accept` keeps state `connecting` (the UI shows "waiting for the host"); if a host appears later it offers again.
- `send`, `sendBlob`, `onMessage`, `onBlob`, `onBlobProgress` only concern the partner. Traffic from any other peer is dropped. `send` before `open` is dropped silently.
- Incoming game messages are validated lightly: must be an object with a string `t`. Incoming blobs must carry a `BlobMeta` with a known `kind`, a string `mime` and a numeric `bytes` equal to the data's byte length; others are dropped.
- If the partner leaves (peer-leave event or `bye`), state becomes `closed`. `close()` sends `bye`, leaves the link, state `closed`. After `closed` nothing is delivered.
- `rttMs` returns null (the Room measures round trips).

```ts
// src/net/room.ts
export interface StartInfo {
  grid: BeatGrid;          // in THIS browser's clock
  firstAttacker: PlayerId;
  firstPhrase: number;
}
export type RoomEvent =
  | { type: 'peer'; name: string }            // hello received
  | { type: 'ready'; local: boolean; peer: boolean }
  | { type: 'synced'; offsetSec: number; rttMs: number }
  | { type: 'theme'; theme: ThemeOffer }      // guest: the host's theme offer arrived
  | { type: 'start'; info: StartInfo }
  | { type: 'rematch'; local: boolean; peer: boolean }
  | { type: 'state'; state: TransportState }  // transport state changed (closed = the friend left)
  | { type: 'versionMismatch' };
export const PROTOCOL_VERSION = 1;
export interface RoomOptions {
  transport: Transport;
  clock: Clock;
  name: string;
  tunables: Tunables;                       // host: sent to the guest; guest: overwritten in place with the host's values
  /** Schedules a callback; defaults to setTimeout. Injected in tests. Used only for ping pacing, never for beat timing. */
  defer?: (fn: () => void, ms: number) => void;
}
export class Room {
  constructor(opts: RoomOptions);
  readonly role: 'host' | 'guest';
  readonly localPlayer: PlayerId;           // host 0, guest 1
  readonly peerName: string | null;
  readonly localReady: boolean;
  readonly peerReady: boolean;
  readonly synced: boolean;
  /** Host clock minus this clock, seconds (0 on the host). */
  readonly clockOffsetSec: number;
  readonly rttMs: number | null;
  readonly theme: ThemeOffer | null;
  setName(name: string): void;              // re-sends hello
  setReady(ready: boolean): void;
  /** Host only: set and send the theme offer. Default theme is the generated click track at 120 BPM. */
  setTheme(theme: ThemeOffer): void;
  /** Host only; no-op unless both are ready and the guest is synced. Sends tunables then start, and emits `start` locally. */
  start(leadSec?: number): boolean;
  /** Ask for a rematch. When both have asked, the host starts a new match automatically (first attacker flips each match). */
  requestRematch(): void;
  on(cb: (e: RoomEvent) => void): Unsubscribe;
  leave(): void;                            // sends leave, closes the transport
}
```

Room rules:

- When the transport is (or becomes) `open`, both sides send `hello {name, v: PROTOCOL_VERSION}`; a hello with a different `v` emits `versionMismatch` and the room does not proceed. The host also sends its current `theme` and `tunables`.
- **Clock sync (guest drives):** after `hello`, the guest sends 8 pings about 120 ms apart: `ping {id, t0}` with `t0` its clock. The host answers at once with `pong {id, t0, t1}` with `t1` its clock. For each pong at guest time `t3`: `rtt = t3 - t0`, `offset = t1 - (t0 + t3) / 2`. Keep the offset of the lowest-rtt sample; after the last pong (or 3 s, whichever first, with at least one sample) emit `synced`. The guest repeats one ping every 5 s afterwards while in the lobby and updates the estimate when a lower-rtt sample arrives; pinging stops at `start`.
- **Ready:** `setReady` sends `ready`. A guest's ready is only sent as true once it is synced (remember the wish and send it when sync completes).
- **Start (host):** `startTime = clock.now() + leadSec` (default 3); `bpm = foldBpm(theme.bpm)`; `firstPhrase = tunables.countInPhrases`; `firstAttacker` 0 for the first match, flipping each rematch. Sends `tunables`, then `start`. The guest converts: `localStart = msg.startTime - clockOffsetSec` and copies the received tunables into its own tunables object in place (`Object.assign`). Both emit `start` with a grid in their own clock. Ready flags and rematch flags reset to false at start.
- **Rematch:** `requestRematch` sends `rematch`; when the host has both, it calls the same start routine.
- `leave` message or transport `closed`: emit `state` with `closed`.
- The Room ignores duel messages (`plant`, `commit`, `parry`, `resolve`, `state`); `DuelSession` listens on the same transport for those.
