# Brief 1.6: browser smoke test of the bot match, and fixing what it finds

**Goal.** Nobody has yet run the game in a browser. Set up Playwright, drive a complete bot match to the victory screen in real Chromium, and fix every runtime bug that stops it or prints console errors. After this task `pnpm e2e` proves the game runs end to end with no human.

**Read first:** `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/briefs/1.4-app-shell.md` (what the app shell was meant to do), then `src/main.ts`, `src/app/`, `src/scenes/`, `src/stage/`, `src/ui/`, `src/debug/`.

**Files you own:** `playwright.config.ts`, `tests/e2e/**`, and for bug fixes `index.html`, `src/main.ts`, `src/style.css`, `src/app/**`, `src/scenes/**`, `src/stage/**`, `src/ui/**`, `src/debug/**`, plus their unit tests. If the bug is in `src/core`, `src/net`, `src/audio` or `src/input`, do not edit those (another agent is changing `src/core/session.ts`, `src/audio/engine.ts`, `src/net/bot.ts` right now): work around it if trivial and report it precisely with file and line.

## Setup

- `@playwright/test` 1.65.1 is already installed. Install only Chromium, inside the project: run `pnpm exec playwright install chromium` with the environment variable `PLAYWRIGHT_BROWSERS_PATH=0` (keeps the browser in `node_modules`). Do not install system dependencies or anything global. If the download is blocked, stop and report it.
- `playwright.config.ts`: set `process.env.PLAYWRIGHT_BROWSERS_PATH ??= '0'` at the top so `pnpm e2e` works without the variable; `testDir: 'tests/e2e'`; Chromium only; `webServer` runs `pnpm build && pnpm preview` on port 4173 (`reuseExistingServer: false`, generous timeout); `use.baseURL` `http://localhost:4173`; viewport 1280x720; launch args `--autoplay-policy=no-user-gesture-required`; `outputDir: 'test-results'`; reporter `list`; retries 0; `workers: 1`; test timeout 120 s; screenshots kept on failure.
- Make sure `pnpm test` (Vitest) does not pick up `tests/e2e`, and ESLint and `tsc` accept the new files.

## Tests (`tests/e2e/bot-match.spec.ts`)

A shared fixture collects `console` messages of type `error` and `warning` and `pageerror` events and fails the test if any occurred (allow-list nothing unless you can justify it in a comment).

1. **Title loads**: `/` shows the title and the three buttons; "Create a room" and "Join a room" have exactly those labels.
2. **A bot match runs to victory unattended**: open `/?debug=1&bot=1&autoplay=1&bpm=180&seed=3&botAccuracy=0.4&tunables=` + a JSON that shortens the match (for example `{"startHealth":30}`; choose values so a best-of-three finishes in well under 60 s of real time), click the bot button, wait for the victory screen. Assert: the banner showed a count-in, then ATTACK!/PARRY!/WATCH states along the way (sample the `banner` test id a few times); health `data-value`s changed during play; the victory screen names a winner; `window.__ttt.session.state.phase === 'matchOver'` and `actWins` has a 2 in it. Save screenshots mid-duel and at victory into `test-results/screens/` (`bot-duel.png`, `bot-victory.png`).
3. **A human click plants a strike**: open `/?debug=1&bot=1&bpm=120&botAccuracy=1`, start, wait until the banner says ATTACK!, then click inside the play area a few times roughly on half-beats (read `window.__ttt` for the clock and grid, or simply click several times 250 ms apart); assert that `session.state.strikes.length` grew or that planted discs appeared, and that Stamina `data-value` for player 0 dropped.
4. **Rematch**: from the victory screen of test 2's setup, click Rematch and assert a new count-in starts and health is back to full.
5. **Debug overlay**: with `?debug=1` the overlay shows a moving beat counter and a number input for every tunable; editing one (for example `missDamage`) changes `window.__ttt.app.tunables.missDamage`.

The audio clock must actually advance in headless Chromium for any of this to work. If `AudioContext.currentTime` does not advance there, find the launch flags that make it advance (for example a fake audio device flag) rather than faking the clock in app code.

## Fixing

Run the tests, read failures, fix the app, repeat until all pass three runs in a row. Look at the screenshots you saved (open them with your image-reading tool) and fix anything plainly broken: nothing drawn, HUD off-screen or overlapping badly, targets not visible, banner unreadable. Do not restyle; final art comes later.

## Checks that must pass

`pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm e2e`, `pnpm exec prettier --check src tests playwright.config.ts`. Shut down any server or browser you started.
